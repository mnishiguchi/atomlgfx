# LovyanGFX 1.3.0 移行検証 — 2026-11-22

Issue #6 の移行を、ESP32-S3 + ILI9488 と8 MB octal PSRAM で確認した。
Elixir 公開 API、AtomVM、ESP-IDF は維持し、LovyanGFX の構築方法と DMA の完了待ちを変更した。

## 構成

| 項目 | 値 |
| --- | --- |
| 基準の main | `ed7f26b` |
| 更新前 LovyanGFX | 1.2.19、`6f6e9a052fc719ecb2b42640b0207215050d2560` |
| 更新後 LovyanGFX | 1.3.0、`dd228d15a03900ce658fd62e120dc7cc489915dd` |
| AtomVM | `e2cacc998f455ad66b1aa9e6391f7b32928cc38d` |

| 接続機器 | ESP32-S3 QFN56 revision v0.2、8 MB flash、8 MB octal PSRAM |
| CPU / PSRAM | 160 MHz / 80 MHz |
| パネル | ILI9488、回転1、480x320 |

通常モードは実行時60 MHz SPI、`nif` は構築時20 MHz SPI を使う。
更新前後の `perf` はともに160 MHz CPU・60 MHz SPI・PSRAM 有効で測定した。

## 構築の変更

- `native/cmake/lovyangfx.cmake` で1.3.0の4つの hub と独立した翻訳単位を明示。
  個別の `.inl` を重複してコンパイルしない。touch 無効時は touch hub を除外する。
- `esp_lcd`、`esp_mm`、`nvs_flash` を ESP-IDF 依存へ追加。
- 旧 I2C は `common.inl` と platform hub の生成 overlay で維持。
  置換位置が消えた場合は構築を停止する。submodule のソースは変更しない。
- `LGFX_PORT_DISABLE_SPI_SCT` を切り分け用に追加。既定は OFF（SCT 有効）。
- CI にソースの存在・重複、touch の選択、I2C overlay、SCT 無効化の設定検査を追加。

ESP32-S3 は `build --fullclean --target esp32s3 --component . --sdkconfig ...` で全再構築。
SDK の追加設定は Getting Started と同じ8 MB flash・octal PSRAM・80 MHz の4項目を使った。
ESP32 は別の SDKCONFIG と構築ディレクトリで、Elixir 用パーティションを指定して構築した。

## 最終画像とメモリー

両画像のアプリ領域は `0x1c0000`（1,835,008 bytes）。下表は追加 SDK defaults を含む
構築時と同じ環境での `idf.py size` と `.bin` のサイズである。

| 項目 | ESP32-S3 + PSRAM | ESP32（コンパイル確認のみ） |
| --- | ---: | ---: |
| `.bin` | 1,803,520 bytes | 1,795,760 bytes |
| アプリ領域の空き | 31,488 bytes（2%） | 39,248 bytes（2%） |
| Flash Code | 1,373,630 bytes | 1,375,094 bytes |
| Flash Data | 284,549 bytes | 281,725 bytes |
| DIRAM | 148,423 bytes / 341,760 bytes | — |
| IRAM | 16,384 bytes / 16,384 bytes | 121,007 bytes / 131,072 bytes |
| DRAM | DIRAM 内 data 22,224 + bss 19,728 bytes | 38,456 bytes / 180,736 bytes |

ESP32-S3 の DIRAM にはコード106,471 bytesも含む。IRAM の固定領域と合わせて読み、
共有可能な DIRAM の残り193,337 bytesを確認した。PSRAM は起動時に8 MB を heap へ追加しており、
上表の静的メモリーとは別である。PSRAM のピーク使用量は未計測。
アプリ領域残量の警告は両構成で発生した。旧 I2C の実行時警告も残るが、ネイティブ構築で新しいコンパイラー警告はなかった。

`b29794fe6dbae18b44763eac8274acb447bd4ea1d1d8837bad3a8159460adb19`。
これは下記の実機モードで起動ログに出た SHA と一致する。

## DMA の監査と修正

上流の [1.3.0 リリースノート](https://github.com/lovyan03/LovyanGFX/releases/tag/1.3.0) に従い、
転送元ではなく転送先の `waitDMA()` を待つ。

| 対象 | 対応 |
| --- | --- |
| 通常・リスト・領域指定の sprite 転送 | 転送先を保持する RAII guard で、途中 return も含めて完了待ち |
| 回転・拡大縮小 sprite 転送 | 同じ guard を適用 |
| 表示用の PSRAM 短冊 | LCD の完了を待ってから描画中の参照を解除し、次の短冊へ進む |
| RGB565 の行バッファ | `pushImage()` 後に待ち、次の行による上書き・最後の解放を安全にする |
| JPEG 入力 | 入力を同期的に復号。画像転送用のバッファ管理は上流の通常 API が担当 |

通常 NIF とバイナリーバッチは同じ装置層を使うため、バッチの次の命令や NIF から戻った直後に
送信元を変更・色深度変更・削除・再作成できる同期契約を維持する。
独自の `heap_capable_dma()` 判定はなく、DMA 適性と PSRAM の cache sync は上流バスに任せる。

## 実機結果

| モード | 結果 |
| --- | --- |
| `nif` | 直接 NIF、RGB565、バッチ、不正引数、480x320、正常終了 |
| `smoke` | 図形・文字、クリップ、JPEG、画像、色・パレット、タッチ probe、正常終了 |
| `sprites` | スプライトの描画と正常終了 |
| `dma` | 二重の `startWrite` を保持したまま38,400 bytesの転送元を40回再利用。直接呼び出し・バッチ内での再描画、色深度変更、削除、再作成が正常終了 |
| `perf` | 下表の計時と正常終了 |
| `moving_icons` | 45秒の記録中、6オブジェクトで5 FPS の統計を継続出力 |
| `all` | smoke、基本図形、文字、スプライト、sprite protocol と正常終了 |

PSRAM 検出、`SPI SRAM memory test OK`、8192K の heap 追加、`psram_sprites=1` を確認した。
上記の採取中に panic、heap corruption、watchdog による再起動はなかった。
確認はシリアルログによる。画素の外観と物理タッチ操作は目視確認していない。
`dma` は API とライフサイクルの動作確認であり、LCD の画素読み戻しによる一致試験ではない。
表示用短冊の完了待ちはコード監査で確認し、この専用経路の実機テストは未実施。

## 性能比較

各120命令、単回の計測。単位は us。

| 項目 | 1.2.19 | 1.3.0 |
| --- | ---: | ---: |
| 矩形バッチの Elixir 符号化 | 275,366 | 291,779 |
| 線バッチの Elixir 符号化 | 267,468 | 278,332 |
| 個別の矩形描画 | 448,070 | 453,460 |
| 矩形バッチ送信 | 80,119 | 80,160 |
| 個別の線描画 | 422,959 | 428,473 |
| 線バッチ送信 | 81,816 | 81,944 |

矩形・線のバッチ送信時間はほぼ同じだった。この測定は大きな PSRAM sprite の SCT 転送を
単独で比較するものではなく、DMA の速度改善を示す結果としては扱わない。
Elixir 符号化はネイティブ更新の影響を受けない処理であり、今回の単回差から原因は判断しない。

## ホスト側の検査

- 既存の105試験、ルート・例示アプリの整形と警告をエラーにするコンパイルが成功。
- ExDoc、操作参照の同期、REUSE、justfile の整形が成功。
- CMake の旧 I2C + touch 有効、新 I2C + touch 無効 + SCT 無効の設定検査が成功。
  後者はソース選択の検査であり、そのファームウェアの実機検証ではない。
- Hex は既存キャッシュを使い、`HEX_OFFLINE=1` で実機アプリを構築した。

## 残る確認範囲

- Core2 は ESP32 向けのコンパイル確認のみ。実機での電源・画面・I2C タッチの回帰確認は未実施。
- CoreS3 は ESP32-S3 の基板制御コードを含めて構築したが、その基板での起動・画面・タッチは未確認。
- PSRAM のピーク使用量、長時間の耐久動作、SCT 無効版の実機比較は未計測。
