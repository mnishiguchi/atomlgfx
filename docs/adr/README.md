# 設計判断記録（ADR）

長期的な設計判断とその理由を残します。日常の利用方法は [Getting Started](../getting-started.md)、
現在の内部構成は [構成](../architecture.md) を参照してください。

## 現在の判断

- [ADR 0003: 制御器を中心としたパネル・タッチ対応](0003-controller-first-panel-and-touch-support.md)

現在の API やセットアップ手順としては使わないでください。

## 追加・更新する場合

- 1件につき1つの判断を記します。API の意味、実行方式、所有権、バッファー、互換性などが対象です。
- 状態は `提案中`、`採用`、`置換済み`、`非推奨` を使います。合意後は同じ文書を `採用` に更新します。
- 判断を変更・置換するときは新しい ADR を作り、旧文書を残して相互にリンクします。
- 計測値や一時的な調査は `../worklog/` に置き、関連する ADR から参照します。
- 操作契約が変わる場合は、`ops.def`、実装、`../protocol.md`、生成物も更新します。

ファイル名は `NNNN-short-title.md`、作業記録は `../worklog/YYYYMMDD-short-topic.md` とします。
